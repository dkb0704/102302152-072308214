# 校园失物招领实现方案

依据：已提交的 Figma 原型、作业要求及周兴宇 PR #1 的16项验收计划。
目标：下载后在 Chrome 直接打开 index.html 即可演示核心流程；另提供 Python 3.9+ 标准库服务支持多个浏览器共享 SQLite 数据。

## 范围与取舍
纯本地版最容易运行，但不能实现跨浏览器信息共享；只提供服务器版又不满足直接打开 HTML 的要求。因此共用一套原生 HTML/CSS/JS 界面，采用本地存储和服务器 API 两种适配器。不使用框架、构建步骤、外部字体/CDN、照片上传、地图、聊天或实名认证。

## 页面与规则
蓝白色响应式界面延续原型：首页（招领/寻物）、发布、搜索、详情、我的发布、成功与确认提示。桌面以内容卡片网格展示，窄屏单列。
默认展示进行中的信息，可选包含已结束；我的发布保留所有状态。名称包含搜索，忽略首尾空白和英文大小写；空白关键词不提交，清空后可重新浏览。类别与地点筛选按 AND 组合。按发布时间倒序，ID作次级稳定排序。
类型 lost/found；状态 active/closed，文案寻找中/待认领→已找回/已归还。只能从 active 结束为 closed，须确认，取消不写入。结束后详情、列表、我的发布一致。
字段：id、type、name（1–40字）、category（校园卡/钥匙/数码/生活用品/书籍/其他）、place（1–60字）、occurredAt（含时区ISO时间，不能晚于现在）、contact（1–100字）、description（0–500字）、status、createdAt、isMine。去除首尾空格；正文用 textContent 渲染；错误保留表单。
公开联系方式之前显示说明；复制失败时允许手动选择，不虚报成功。种子数据明确标记“示例”，联系方式为无效演示值。

## 身份与边界
首次打开生成32字节随机浏览器管理凭证并保存在本机。HTTP模式请求通过 X-Owner-Key 传递，服务器仅存凭证哈希，每次修改核对；列表不返回他人凭证或哈希。无账号密码、无身份认证。清除浏览器数据或换浏览器会失去旧记录的管理权限，发布前明确提示。不提供找回管理凭证功能。
file模式仅本机数据，可通过开发者工具篡改，不能视为真实权限安全。HTTP模式的权限由服务器校验；默认仅监听127.0.0.1，是课程演示服务，不作为公网生产系统部署。两种模式的数据互不自动同步。

## 数据与错误
JS core负责表单校验、筛选和本地状态规则；store负责持久化/API，app负责渲染和交互。Python服务重复执行输入和所有权校验，用SQLite事务写入。只提供白名单静态文件，不暴露数据库、Git和测试文件。HTTP错误用JSON返回；无连接、损坏存储、写入失败均显示错误，不显示成功或悄悄覆盖数据。中途失去服务时不自动切换本地模式。

## 验证
Node自带test/assert验证真实业务函数和本地适配器，Python unittest验证真实数据库和HTTP边界。覆盖空白、长度边界、未来时间、排序、过滤、权限、重复结束、存储失败和不泄露管理凭证。Chrome检查完整发布、搜索、空结果、确认取消、结束、刷新保留和响应式布局；通过HTTP测试两个独立凭证查看同一条信息并拒绝非发布者修改。
